
# ЯНУШ (JANUS) | AI Психосимулятор для Педагогов

Профессиональный тренажер на базе Google Gemini 3.0, имитирующий сложные разговоры с подростками на основе акцентуаций по А. Личко.

## 🚀 Коммерческая готовность

Приложение готово к использованию как MVP (Minimum Viable Product).

### Основные возможности:
- **Chaos Engine**: Динамическая сборка сценариев (Психотип + Инцидент + Фоновый конфликт).
- **Secure Auth**: Регистрация пользователей с SHA-256 хэшированием паролей.
- **Paywall**: Разграничение доступа к сложным акцентуациям (Premium).
- **AI Analysis**: Вердикт «комиссии экспертов» после каждого сеанса.

### Как запустить настоящую оплату:
1. В файле `constants.ts` укажите ваш `PAYMENT_PROVIDER_URL`.
2. В `SetupScreen.tsx` замените имитацию ожидания в функции `processPayment` на редирект: `window.location.href = ...`.
3. Для полноценной защиты данных рекомендуется перенести `localStorage` на **Supabase** (PostgreSQL) или **Firebase Auth**.

## 🛠 Установка

1. **Клонируйте репозиторий**:
   ```bash
   git clone https://github.com/your-username/janus-ai.git
   ```
2. **Установите зависимости**:
   ```bash
   npm install
   ```
3. **Настройте API Key**:
   Создайте `.env.local` и добавьте `API_KEY=ваш_ключ_из_google_ai_studio`.

## 🛡 Безопасность
- Пароли хэшируются на клиенте.
- Внедрен `SecurityShield` для защиты от инспекции кода в браузере.
- Поддерживается Vercel Proxy для обхода блокировок API.

## 📋 Статус проекта (март 2026)

### Что было сделано

Проект столкнулся с блокировкой: ТСПУ (Роскомнадзор) режет трафик к западным платформам (Cloudflare, Vercel, Netlify) после примерно 15–16 КБ данных, из-за чего сайт открывался, но «висел» и не работал для пользователей в России.

Чтобы обойти это, инфраструктура была разделена на две части:

1. **Фронтенд (то, что видит пользователь)** — теперь загружается с российского хостинга **Beget** (`yanush-sim.ru`). Сюда ТСПУ не добирается, сайт открывается мгновенно.
2. **Бэкенд (запросы к нейросети)** — остался на **Cloudflare Pages** и доступен по адресу `api.yanush-sim.ru`. Фронтенд обращается к нему напрямую.

Конкретно в коде:
- Созданы серверные функции для Cloudflare Pages: `functions/api/proxy.js` (запросы к ИИ) и `functions/supabase-proxy/` (запросы к базе данных). Оба файла умеют отвечать браузеру с нужными заголовками, чтобы не было ошибок CORS.
- Адрес API в коде сайта изменён с относительного (`/api/proxy`) на абсолютный (`https://api.yanush-sim.ru/api/proxy`).
- Настроена автоматическая сборка и выгрузка на Beget: теперь при каждом коммите в ветку `main` GitHub сам собирает сайт и заливает его на хостинг по FTP (файл `.github/workflows/deploy.yml`).

### Что нужно сделать дальше

Чтобы проект заработал на новой инфраструктуре, нужно выполнить несколько ручных шагов в панелях управления:

**1. Настроить секреты в GitHub** (один раз)

Перейдите в репозиторий → **Settings → Secrets and variables → Actions** и добавьте три секрета:
- `FTP_SERVER` — адрес FTP-сервера Beget (узнать в панели Beget, обычно `ftp.беget.com` или IP-адрес)
- `FTP_USERNAME` — логин FTP
- `FTP_PASSWORD` — пароль FTP

После этого каждый пуш в `main` будет автоматически обновлять сайт на Beget.

**2. Подключить репозиторий к Cloudflare Pages** (один раз)

В панели **Cloudflare → Pages → Create a project** выберите этот репозиторий GitHub. Cloudflare сам будет деплоить серверные функции из папки `functions/` при каждом пуше.

В разделе **Settings → Environment variables** добавьте:
- `API_KEY` — ключ от ProxyAPI (для запросов к Gemini)
- `SUPABASE_URL` — адрес вашего проекта Supabase (если используется)
- `SUPABASE_ANON_KEY` — публичный ключ Supabase (если используется)

**3. Настроить DNS**

В панели управления доменом `yanush-sim.ru` убедитесь, что:
- Корневой домен (`yanush-sim.ru`) смотрит на IP Beget (`87.236.16.28`)
- Поддомен `api.yanush-sim.ru` настроен как CNAME на домен вашего проекта в Cloudflare Pages (с включённым проксированием Cloudflare — «оранжевое облако»)
